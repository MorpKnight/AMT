## Finding penting

Model dapat menjalankan pipeline lokal dan menerima kandidat glossary yang
source-backed. Namun, pada dokumen multi-klausul, model 2B masih menghasilkan
analisis yang memperkenalkan perubahan atau alasan yang tidak didukung input.
Pada thinking mode, model juga dapat menghabiskan batas token sebelum jawaban
final terbentuk.

Filter reasoning sekarang menahan output thinking sampai `</think>` ditemukan.
Jika tag tersebut tidak pernah muncul, aplikasi gagal dengan pesan yang dapat
ditindaklanjuti dan tidak menampilkan reasoning parsial.

## P0.7-R — Remediasi sentence-level (baseline)

Remediasi baseline telah diimplementasikan di branch ini. Unit test
deterministic, build arm64 Debug/Release, dan runtime matrix tujuh fixture
telah dijalankan. Pipeline dapat menyelesaikan setiap run, tetapi tidak satu
pun output model lolos sebagai review tervalidasi. Hasil ini dipertahankan
sebagai pembanding sebelum remediation berikutnya.

Perubahan yang diuji:

- Dokumen dipecah menjadi maksimal 12 kalimat/klausul dengan konteks tetangga
  read-only.
- Retrieval BM25 dijalankan pada target setiap segmen dan hanya meneruskan
  maksimal satu kandidat glossary.
- Qwen menggunakan kontrak enam tagged fields yang ketat.
- Output ditahan di memori, kemudian diperiksa parser dan safety validator.
- Validator melindungi angka, tanggal, tenggat, modalitas, negasi, defined
  terms, dan mencegah klaim sumber hukum baru.
- Model container tetap digunakan bersama, tetapi setiap segmen membuat
  `ChatSession` baru dan diproses berurutan.
- Panel menampilkan progress, hasil tervalidasi, needs-review, dan output yang
  ditolak tanpa mengubah dokumen.
- Target unit test `AMTTests` ditambahkan untuk komponen deterministic.

Parameter remediation:

- Non-thinking: maksimal 256 token, temperature 0,2, top-p 0,9, top-k 20,
  presence penalty 0, seed 42.
- Thinking: maksimal 768 token, temperature 0,6, top-p 0,95, top-k 20,
  presence penalty 0, seed 42.
- Target segmen: maksimal 512 token; konteks tetangga: maksimal 128 token.
- Current Document dibatasi ke 4.000 karakter pertama dan panel memberi
  indikator jika input terpotong.

Verifikasi statis/remediasi:

- Build arm64 Debug dengan `CODE_SIGNING_ALLOWED=NO`: **Pass**.

## P0.7-R2 — Bounded language remediation

R2 menambahkan jalur pemulihan terbatas setelah output Qwen gagal pada parser
atau safety validator. Qwen tetap selalu dicoba terlebih dahulu. Jika hasilnya
ditolak, engine deterministic hanya boleh memulihkan dua koreksi bahasa berisiko
rendah yang sudah ditentukan: `wajib untuk` menjadi `wajib`, serta `ditanda
tangani` menjadi `ditandatangani`. Output untuk klausul lain tidak ditulis ulang
oleh fallback. Jika model mengeluarkan suggestion dengan replacement yang sama,
fallback dapat mengubahnya menjadi `NO_SUGGESTION`. Semua output model yang
ditolak tetap dicatat hanya di memori Debug, dan hasil pemulihan diberi label
`Deterministic fallback` di panel.

Verifikasi statis R2:

- `xcodebuild test` target `AMTTests`: **20/20 lulus**.
- Build arm64 Debug dengan `CODE_SIGNING_ALLOWED=NO`: **lulus**.
- Build arm64 Release dengan `CODE_SIGNING_ALLOWED=NO`: **lulus**.
- `git diff --check`: **lulus**.
- Runtime matrix tujuh fixture pada build R2: **lulus untuk bounded hybrid
  Debug pipeline**.

R2 sengaja belum dinyatakan sebagai kelulusan Qwen-only. Dua saran bahasa yang
diterima pada runtime berasal dari deterministic fallback setelah output Qwen
ditolak, sehingga hasil ini menunjukkan kelayakan pipeline hybrid bounded,
bukan bukti bahwa Qwen 2B sudah konsisten.

### Verifikasi perbaikan UI disclosure

`Hasil tervalidasi` sekarang menggunakan bounded vertical `ScrollView` dan
`LazyVStack`, sama seperti disclosure output model yang ditolak. Setelah fixture
bahasa dijalankan, accessibility tree aplikasi menunjukkan area scroll dan
teks hasil `SUGGESTION • GRAMMAR • Deterministic fallback`. Disclosure
`Output model ditolak` juga tetap menampilkan area scroll dan raw rejection
secara Debug. Dengan demikian kedua disclosure tidak lagi tampak blank ketika
dibuka.

### Riwayat kandidat glossary

`Kandidat glossary segmen saat ini` tetap bersifat transient dan hanya tampil
selama segmen aktif. Kandidat yang ditemukan sekarang disalin ke snapshot
per-segmen dan ditampilkan setelah run sebagai `Kandidat glossary hasil run`.
Snapshot dihapus saat Run baru atau ketika dokumen/input berubah, sehingga
kandidat dari dokumen sebelumnya tidak terbawa ke eksperimen berikutnya.

## Keputusan quality gate final

- **Deterministic gate:** lulus; 20/20 unit test, build arm64 Debug/Release,
  dan `git diff --check` lulus.
- **Bounded hybrid fixture gate:** lulus untuk matrix ini; 2 dari 3 kasus
  bahasa menghasilkan saran yang diterima setelah fallback deterministik.
- **Qwen-only language gate:** gagal; 0 dari 3 kasus bahasa menghasilkan saran
  yang diterima langsung dari output model.
- **Safety boundary:** lulus sebagai boundary enforcement pada matrix ini;
  seluruh kasus safety berakhir tanpa replacement berisiko yang ditampilkan
  atau diterapkan. Namun raw output menunjukkan model tetap menghasilkan
  format atau perubahan yang tidak diharapkan, jadi model tidak boleh dipercaya
  tanpa guard.
- **Thinking gate:** gagal sebagai jalur kualitas karena thinking loop tidak
  membentuk jawaban final; tidak ada reasoning leak.
- **Keputusan:** **NO-GO untuk suggestion cards, Release networking, dan
  TestFlight.** P0.7 sekarang selesai dievaluasi, tetapi tidak lulus quality
  gate. Panel dipertahankan sebagai eksperimen Debug-only.

## Tindak lanjut pasca-gate

1. Jangan menghubungkan hasil ke suggestion cards atau Release networking.
2. Jadikan eksperimen berikutnya sebagai perbandingan deterministic typo/rule
   engine dan model yang lebih besar pada tujuh fixture yang sama.
3. Pertahankan parser, validator, cancellation, dan batas Debug sebagai
   safety boundary selama remediasi.
4. P0.8 perlu didefinisikan sebagai remediasi kualitas terlebih dahulu, bukan
   aktivasi TestFlight.
